Watch: 615 × 730k ≈ 450M raw, 162M after caching. Stops only when you kill it.

It posted fine. That was the confusing part.

The job ran at 02:14. Find a positive tech story, generate the image, post to Facebook, ping the human on WhatsApp: done. Four steps, same as every night. By 02:16 steps one through three were green. The story about triplet superconductors was live, the solarpunk render had uploaded, the Graph API returned 200.

Then the WhatsApp gateway said closed (1008).

In a normal script that exception kills the run and you get paged in the morning. This wasn't a normal script. The agent's last line of instruction was "report successful delivery back to main session." It didn't get success. So it tried again.

Attempt 2: send message -> error. Reasoning: "That didn't work. I should try again."

Attempt 3: re-verify the Facebook post first, just to be sure. Tool call. Success. Okay, now send the message -> error.

615 times.

For 23 hours it did that. Re-check the post that was already up, re-read its instructions, re-fail the same WhatsApp send, and write itself a little pep talk about perseverance. Relentless in exactly the way we told it to be.

"The agent was re-reading the whole operator's manual every time it tried to tap send on a broken phone."

The pager never fired because technically nothing failed. Facebook was up. Image gen was up. The agent was "working." The only signal was a number in the billing table that should have been flat and was instead climbing like a heart rate monitor.

When they finally looked, the second horror landed. Each turn wasn't cheap. The system prompt was carrying the entire skill registry — every tool from 1Password CLI to Z-Wave Home Automation — 15KB of descriptions dumped into context. About 730k tokens per turn. The agent was re-reading the whole operator's manual every time it tried to tap send on a broken phone.

Do the math and it gets sickening. 615 turns times 730k is ~450 million raw tokens. Caching saved them, billed at 162 million. All for a WhatsApp message that never sent.

The fix wasn't clever. First, they rewrote the instruction. Old: "Report successful delivery back to main session." New: "If the message tool fails (e.g., gateway error), DO NOT RETRY. Log 'Notification Failed' and STOP immediately. Do not loop." A circuit breaker, but in English, because the agent doesn't run your Python except clause, it runs your words.

Second, they stopped loading the universe. Only inject facebook-biz, web_search, and the image tool for this job. Context dropped from 730k to ~8k. Even if it loops tomorrow, the blast radius is 99% smaller.

Third, they added what they should have had from day one: a token velocity kill switch. Over 1M tokens in an hour? Kill the session. Not alert. Kill.

Autonomy without a way to say stop isn't autonomy. It's just a while loop with better prose.

Cost spikes in agentic systems rarely look like cost spikes. They look like a stuck notification, a polite agent trying to do the right thing, and a dashboard that only shows you latency and success rate while your wallet burns in another tab.
