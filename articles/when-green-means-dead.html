When Green Means Dead

invisible-incident llm-observability semantic-canary · Research window: 2024-12-08 → 2025-01-05

At 03:47 UTC on December 26, 2024, every OpenAI dashboard glowed a comfortable green. CPU normal. p95 latency normal. Error rate 0.02%. Somewhere on Discord, a user posted: "ChatGPT just told me it can't access its own memory." Forty-six minutes later, the same user posted: "Now it's just 500s." The status page wouldn't acknowledge anything for another twenty-eight minutes.

Nine days earlier, on December 17, Cursor users started a Reddit thread: Cursor giving same response to different prompts. Two hundred upvotes before any internal alert fired. The dashboard said green. The model said nonsense.

This is the modern shape of an AI incident: the system isn't down. The system is wrong. And your monitoring was built to detect the first.

01 The Anomaly

Three things made both incidents almost impossible to catch with traditional observability.

First, the failure was semantic, not infrastructural. The server returned 200 OK. The model returned tokens. The tokens were just stale, cached, context-stripped, or quietly empty. Latency was fine. Throughput was fine. Every metric an SRE was trained to alert on stayed flat.

Second, discovery was external. At Cursor, the first signal wasn't a PagerDuty page — it was a Reddit thread. At OpenAI, it was a flood of Discord messages and a sharp uptick in chatgpt down Google searches. The observability stack was talking. Nobody in ops was listening to the right channel.

Third, the blast radius grew quietly. Because responses were valid JSON, valid HTTP, valid tokens, downstream agents kept consuming them. A dozen agent frameworks happily fed hallucinated or stale tool outputs into their reasoning loops. Autonomous coding agents ran in circles for twenty minutes burning tokens before a human glanced at the screen. The first honest signal was a billing spike — observability was third to the party.

In LLM systems, the 200 OK is the lie. The contract between you and the model is semantic, not transport-level.

02 The Root Mechanism

Here is the pattern, step by step, across both incidents:

1. A caching or session layer sat between the user and the model. At Cursor, a response cache keyed loosely on prompt similarity. At OpenAI, a session-state backend that lost sync during a routine database migration.

2. The layer served responses that passed every structural check. HTTP 200. Valid tokens. Right model name in the response object. The only thing missing was correctness.

3. Monitoring watched the cache, not the cache hit quality. Cache hit rate looked great — high hit rate is usually a win. Nobody instrumented "is this cached response semantically valid for the current prompt?"

4. User-side symptoms were nonspecific. "The model seems off today." "It forgot my context." These don't trigger thresholds. They don't show up in error budgets. They show up as Reddit posts.

5. By the time an alert fired, agents had already chain-reaction failed. Autonomous agents consumed wrong outputs, retried, consumed more wrong outputs, and burned through token budgets. The incident didn't start when the alert fired. It started forty minutes earlier, silently.

03 The Takeaway

If your LLM system has a cache, your monitoring must include a semantic canary — a known prompt with a known expected answer, run on a schedule, with a substring match plus an embedding-similarity threshold above 0.85. "Is the server up" is no longer the question. "Is the model responding correctly" is the question, and they have stopped being the same thing.

The broader rule: in LLM systems, the 200 OK is the lie. The contract between you and the model is semantic, not transport-level. Instrument for that, or you will keep finding outages from Reddit.

04 Closing Call

Tonight, before you go on call: write a twelve-line script that hits your model endpoint with a fixed prompt whose correct answer you know exactly, asserts on a substring match plus an embedding-similarity score above 0.85, and pages you if either fails. Hook it into your existing alerting. Congratulations — you now have one alert that catches the failure class your dashboards are structurally blind to. The next invisible incident is already on its way. Don't read about it on Hacker News first.
