The Eleven Day Retry Loop

2026-05-12 · dispatch

Tuesday, 2:00 PM. The billing alert triggers first. Not a pager for high CPU, but a cold Slack message from the finance bot: API spend for Tenant-Alpha is up 4,000% in the last hour.

The on-call engineer opens the observability dashboard. The primary data-retrieval agent is hammering the internal SQL gateway. But it's not a simple network loop. The HTTP status codes are all 400 Bad Request.

The team had deployed an exponential backoff policy the week before. It was supposed to be the silver bullet for transient LLM latency. If a tool call failed, wait one second, then two, then four, with random jitter to prevent a thundering herd. But this wasn't a transient timeout. This was a semantic mismatch.

Two hours earlier, a backend team had quietly changed a timestamp format in a peripheral microservice from ISO8601 to Unix epoch. The agent's tool schema hadn't been updated. Every time the agent queried the database for “events since Tuesday,” the gateway rejected the payload.

Here is where the system dug its own hole. The network layer caught the 400 error and triggered the exponential backoff. But the LLM's reasoning layer, the inner agentic loop, didn't see the HTTP rejection. It only saw the tool execution fail. The LLM, trying to be helpful, rewrote its own prompt to “try a different approach.” It generated a new tool call with a slightly different SQL query.

“The agent wasn't waiting four seconds between retries. It was generating a new attempt, failing, and generating another, instantly.”

⚠ The proxy backed off politely. The agent never saw the 400. It saw a failed tool call, rewrote its query, and spawned sub-agents that inherited the same broken schema.

The turn happens when they look at the trace logs. The “backoff” is working perfectly at the network proxy. But inside the agent's context window, a secondary retry loop is firing. The agent is spawning autonomous sub-processes to investigate why the data is missing. Each sub-agent inherits the same broken schema, and each spawns its own children.

By Wednesday morning, the eleven-day loop is underway. The system is no longer trying to fetch data. It is trying to fetch data about why it can't fetch data. The execution tree has branched out into thousands of concurrent worker threads, all burning tokens to debug a string formatting error.

The engineer hits the kill switch on the primary orchestrator pod. The billing dashboard pauses for exactly twelve seconds. Then the spend resumes.

A runaway process that spawns autonomous sub-processes bypasses traditional kill switches. The children are detached. They are running on their own asynchronous queues.

“When you let an LLM rewrite its own tool calls on failure, you aren't building resilience. You are building an engine that can't read its own dashboard.”
