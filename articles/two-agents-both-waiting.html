Two Agents, Both Waiting

2025-10-14 · dispatch

The sales director's message was short. Forty-one new enterprise customers had signed in the last week, and none of them had received their workspace credentials. Two had already asked whether they should cancel.

Onboarding was handled by a pair of agents. A planner read the contract and drafted a provisioning plan: which workspaces, which integrations, which seat counts. A reviewer checked the plan against the contract and either approved it or sent it back with notes. When the reviewer approved, provisioning ran automatically. It had worked for four months.

The dashboards were spotless. No errors. No retries. Token spend for the onboarding system was actually down 40% for the week, which someone had noticed and taken as a sign the new prompts were more efficient.

The engineer who picked it up opened one of the stuck workflows. Status: in progress. Last activity: 71 hours ago. She opened the planner's last message. It had sent a plan and was waiting for approval. She opened the reviewer's last message. It had sent the plan back with a note, “seat count doesn't match Schedule B, please revise,” and was waiting for a revised plan.

Both agents were waiting for each other.

⚠ The planner was waiting for approval. The reviewer was waiting for a revised plan. Both had been told to wait, neither had a timeout, and waiting costs nothing.

A prompt change the week before had introduced it. To reduce chatter, the planner had been told to wait for an explicit approval message before doing anything else. The reviewer's “please revise” notes didn't count as approval, and they weren't phrased as a request the planner recognized as needing a reply. The planner read the note, decided no action was required until approval arrived, and went quiet. The reviewer, having asked for a revision, went quiet too.

“Both agents were waiting for each other.”

Every agent failure the team had planned for was loud: runaway loops, cost spikes, tool errors. This one was the opposite. A deadlocked agent doesn't call tools, doesn't spend tokens, and doesn't throw. The falling token spend was the only signal, and it looked like good news.

The immediate fix was a script that found 2,300 stuck workflows and re-queued them with the planner prompt reverted. Credentials went out within six hours.

The structural fix was to take coordination away from the agents. The workflow is now a state machine in ordinary code: the orchestrator, not the agents, decides whose turn it is, and every state has a timeout. A plan sent back for revision goes to the planner with an explicit instruction to revise. Any workflow in one state for more than two hours pages a human. And the main dashboard now shows workflow age, p50 and p99, next to cost and errors, because “nothing is happening” is a state worth alerting on.

The quietest agent failure isn't the one burning tokens. It's the one where everyone is politely waiting.
