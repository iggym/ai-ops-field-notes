The model was fine

2024-12-03 · dispatch

The completeness alert fired at 10:42 on a Tuesday. The LLM-as-judge score for the support assistant had dropped from 0.88 to 0.71 in under an hour, and the hallucination detector was flagging answers as “missing required steps.” The on-call engineer, Priya, pulled a sample. The answers were short. Clipped. One refund explanation ended mid-procedure, three steps in.

It looked like a model regression. The provider had announced a minor update the week before, and the shape matched: same questions, worse answers, no code deploys on their side. She opened a ticket with the provider and started the runbook for pinning the previous model snapshot.

The pin went out at 11:20. The score didn't move.

That was the first useful signal. If rolling back the model doesn't change the output, the model isn't the variable. She diffed the full request payloads between a good answer from Monday and a bad one from that morning. The user messages were similar. The model ID was identical. The system prompt was not.

The bad request had an extra line at the bottom: “Keep every answer under 60 words. Customers prefer brevity.”

It came from a feature flag called concise_answers_v2. The growth team had launched an A/B test that morning to see whether shorter answers improved CSAT. The flag lived in the product experimentation tool, not the deploy pipeline, so it never showed up in the change log the on-call engineer checked first. It was serving the new prompt to 30% of traffic.

⚠ concise_answers_v2 was serving a different system prompt to 30% of traffic. The judge was scoring a 60-word cap as 'incomplete'.

The model was doing exactly what it was told. A 60-word cap on a seven-step refund procedure produces a three-step answer, and the judge, correctly, scored it as incomplete. Every alert was true. The diagnosis was wrong, because the system that changed the behavior wasn't in the incident channel, and nobody in the incident channel knew it existed.

“If rolling back the model doesn't change the output, the model isn't the variable.”

The fix took four minutes once they found it: turn the flag off. Scores recovered within the next eval window. The cleanup took longer. The team moved prompt-affecting flags into the same audit trail as deploys, added the active flag set to every trace as span attributes, and taught the alert to group scores by flag variant. A split that clean, 30% bad and 70% fine, would have pointed at the experiment in the first minute.

They also wrote down the thing that stung: in an LLM system, the prompt is code, and anyone who can edit it is shipping to production. The experimentation tool had more deploy authority than the deploy pipeline, and nobody had drawn that box on the architecture diagram.

The provider ticket was closed with an apology. The model was fine. It was doing exactly what it was told — by someone who wasn't in the incident channel.
