The Loop That Ate The Key

2026-05-20 · dispatch

It started with a single customer uploading a scanned invoice containing zero bytes of valid text.

At 11:04 AM, the background worker picked up the job. The worker ran an autonomous agent tasked with extracting key-value pairs from documents. When the PDF parser tool failed on the empty document, it returned a standard Python exception: UnicodeDecodeError: 'utf-8' codec can't decode byte.

Instead of crashing the job, the framework did what its prompt instructed: it caught the error, appended the full stack trace to the agent's memory, and asked the model to try a different extraction strategy.

The model tried again. It called the parser tool with a different encoding flag. The parser failed again. The framework appended that stack trace as well.

⚠ Every retry appended the previous stack trace to the context. Cost per attempt grew with each failure, and the single thread exhausted the key that every other service shared.

In traditional software, a retry loop executes the same function N times. The cost is linear. In an LLM agentic loop, every retry appends the failure history to the context window. Attempt 1 sent 1,500 tokens. Attempt 5 sent 12,000 tokens. Attempt 15 sent 64,000 tokens of nested stack traces, previous attempts, and system instructions.

“In an LLM agentic loop, retries don't scale linearly. They scale quadratically as context windows swell with past stack traces.”

By 11:18 AM, the single thread wasn't just retrying. It was firing ten requests a second. The model was spending 90% of its execution time processing its own past mistakes.

At 11:22 AM, PagerDuty alerted on a total API outage across all production services. Every application using the primary LLM client key was receiving HTTP 429 Rate Limit Exceeded errors. The engineering team assumed they were under an external credential-stuffing attack or facing an upstream provider degradation.

The worker was stuck in a tight loop at iteration #84. It had consumed $2,200 worth of API credits in thirty-two minutes before running out of quota and taking down the rest of the company's production pipelines with it.

The immediate fix was a hard execution cap: maximum 5 tool calls per agent invocation, period. The real architecture fix was removing raw exception strings from the agent's context window entirely.

“When you build agentic loops, never let an LLM decide when to stop trying.”

Software fails deterministically, but an agent fed its own error logs will burn down your entire infrastructure budget trying to prove it can fix them.
